# Подключение из 3x-ui

Эта инструкция относится к Pushok Flow **0.46.0+46**. 3x-ui — панель управления: совместимость определяется протоколом и параметрами конкретного клиента, а не названием панели.

## Поддерживаемый профиль

Можно добавить одну клиентскую ссылку **VLESS**, начинающуюся с `vless://`. Версия 0.37 расширяет поддержку транспортами WebSocket и gRPC поверх TLS.

| Транспорт | Защита | XTLS Vision |
| --- | --- | --- |
| TCP / Raw (`type=tcp` или `type=raw`) | TLS с проверкой сертификата | Необязательно |
| TCP / Raw | REALITY | Необязательно |
| WebSocket (`type=ws`) | Только TLS с проверкой сертификата | Не поддерживается |
| gRPC (`type=grpc`) | Только TLS с проверкой сертификата | Не поддерживается |

Для Vision используется `flow=xtls-rprx-vision`; у WebSocket и gRPC поле `flow` должно отсутствовать или быть пустым. Существующие профили WireGuard `.conf` продолжают работать.

Для **WebSocket** отсутствующий или пустой `path` означает `/`; `host` можно не указывать или оставить пустым. Явный `alpn` допускает `http/1.1` либо `h2,http/1.1`.

Для **gRPC** обязателен непустой `serviceName`; `authority` необязателен и может быть пустым. Поддерживаются обычный режим — без `mode` или с `mode=gun` — и `mode=multi`; `guna` отклоняется. Явный `alpn` допускает `h2` либо `h2,http/1.1`. Для обоих транспортов отсутствующий или пустой `alpn` оставляет выбор ядру.

Явно пустые `sni=` и `fp=` не принимаются, как и в 0.36.0. Если необязательный параметр не задан, используйте штатный QR или клиентскую ссылку из интерфейса 3x-ui: его экспорт пропускает эти пустые поля. Настроенные дополнительные параметры безопасности, включая ECH и закрепление сертификатов, в этот этап не входят и не удаляются при импорте.

VMess, Trojan, Shadowsocks, XHTTP, другие транспорты, произвольные JSON-конфигурации и новые варианты собственного шифрования VLESS в этот выпуск не входят. VLESS без TLS/REALITY и отключение проверки сертификата TLS не поддерживаются. Неподдерживаемые параметры отклоняются с понятным сообщением; они не удаляются из ссылки ради видимости успешного импорта.

Для REALITY нужны соответствующие серверу SNI, публичный ключ, short ID при его наличии и поддерживаемый отпечаток клиента. Приватный ключ сервера в клиент не вводится. Принимаются отпечатки `chrome`, `firefox`, `safari`. REALITY доступен только с TCP / Raw.

Основания формата: [ссылки 3x-ui](https://github.com/MHSanaei/3x-ui/blob/main/docs/content/docs/en/config/share-links.mdx), [спецификация ссылок Xray](https://github.com/XTLS/Xray-core/discussions/716), [REALITY](https://xtls.github.io/en/config/transports/reality.html), [WebSocket](https://xtls.github.io/en/config/transports/websocket.html), [gRPC](https://xtls.github.io/en/config/transports/grpc.html). Таблица выше описывает набор возможностей Pushok Flow, а не все возможности Xray.

## Как добавить

1. В 3x-ui откройте нужного клиента и скопируйте его ссылку, начинающуюся с `vless://`, либо откройте QR этого клиента.
2. В Pushok Flow откройте **Серверы → Добавить профиль** и задайте название.
3. Выберите **Вставить**, **Сканировать QR**, **QR из фото** или **Из файла** для текстового файла с одной ссылкой.
4. После успешного чтения нажмите **Сохранить профиль**. Профиль хранится в прежнем зашифрованном каталоге.
5. Если сохранено несколько профилей, нажмите **Выбрать** у нужного в «Серверах», затем откройте **Главная → Подключить**. Если Android запросит разрешение на туннель, подтвердите его.

При добавлении второго профиля текущий выбор сохраняется. Импорт сам не подключает и не меняет маршруты. Отмена или ошибка не заменяют уже введённый черновик. Если QR находится на том же телефоне, используйте **QR из фото**.

## Если QR содержит подписку

Начиная с v0.45.0 камера, **QR из фото** и текстовый файл распознают HTTPS-ссылку подписки отдельно от клиентского профиля. После чтения нажмите **«Добавить как подписку»**, проверьте источник и название, затем **«Добавить подписку»**. Только последнее нажатие загружает серверы. Ссылка скрыта, а исходный черновик профиля сохраняется при возврате. Можно также добавить ссылку прямо через **Серверы → Подписки → Добавить подписку**.

Подписка должна возвращать поддерживаемые VLESS-ссылки по публичному HTTPS. Ошибка или отмена не меняет сохранённые серверы; успешное добавление не включает VPN. Нажмите **«Выбрать»** у нужного сервера, затем **Главная → Подключить**. Для Telegram proxy, VMess, Trojan и Shadowsocks Flow отдельно объясняет неподдерживаемый тип.

## Прямые маршруты и диагностика

Сохранённый список приложений из «Маршрутов» используется и для VLESS. Android исключает выбранные приложения из туннеля при его создании. Для изменения списка сначала отключите текущее подключение. Недоступные Android пакеты не удаляются из выбора молча.

Статус **«Туннель включён»** подтверждает запуск локального туннеля. Он не доказывает успешную авторизацию у сервера или доступность Интернета. Для VLESS не показывается рукопожатие WireGuard; пока числовая статистика Xray не подключена, недоступные показатели отображаются как «—».

## Обновление

Поддержка новых транспортов меняет код приложения, поэтому требует обычного обновления APK с прежним постоянным сертификатом. Путь: **Профиль → Версия и обновления → Проверить обновления → Скачать → Установить обновление**. Если разрешение ещё не выдано, сначала появится **Разрешить установку**.

Удаление установленного подписанного Pushok Flow не является шагом обновления. После установки поддерживаемые профили можно добавлять внутри приложения без новой сборки. Подписанные рекомендации приложений продолжают обновляться отдельно без APK.

Физическая проверка конкретного профиля 3x-ui, переключения Wi-Fi/мобильной сети, DNS, IPv6 и прямого трафика выбранных приложений остаётся отдельным этапом. Для автоматических проверок используются только искусственные профили; реальные клиентские ссылки в репозитории и журналах не сохраняются.
