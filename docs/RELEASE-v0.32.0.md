# Pushok Flow v0.32.0 — состояние подключения и импорт профилей

Дата: 22.11.2026 (Москва). Версия приложения: `0.32.0+32`.

Статус: исходники подготовлены; проверки полной сборки и публикация ещё не завершены. Последний опубликованный выпуск — v0.31.0.

## Изменения

### Подключение после открытия приложения

Новое подключение доступно после получения актуального, известного состояния выключенного туннеля. Пока первоначальная проверка или проверка после возврата из фона не закончена, нажатие не запускает соединение и не ставит его в очередь. Если профиля ещё нет, после завершения проверки одно явное нажатие открывает редактор «Сохранить и подключить».

При последнем известном включённом туннеле отключение остаётся доступным, даже если новая диагностика ожидается или не смогла прочитать состояние. Ошибка проверки не выдаётся за успешное отключение.

### Общее состояние Android

Операции общего сеанса выполняются в одной последовательной очереди процесса. Пересозданный экран использует ту же очередь и тот же объект туннеля. Старое чтение состояния больше не выполняется параллельно с подключением из нового экземпляра Activity.

Перед включением нативный код проверяет фактическое состояние. Повторный запрос при уже включённом туннеле не применяет конфигурацию заново и не сбрасывает время сеанса. Если состояние прочитать не удалось, новое подключение не запускается.

После ошибки операции состояние уточняется отдельно. Если и эта проверка неудачна, сохраняется последнее известное состояние с признаком неопределённости. Возможность отключить ранее включённый туннель сохраняется.

### Совместимость WireGuard-профилей

Заголовки `[Interface] # комментарий` и `[Peer] # комментарий` разбираются одинаково во всех проходах подготовки конфигурации. Выбранные исключения добавляются в Interface перед первым Peer, а не в конец конфигурации. Сохраняются комментарии, ключевые строки, DNS и IPv4/IPv6 в AllowedIPs; окончания строк приводятся к `LF`.

При сохранении проверяется тот же поддерживаемый приложением формат, который используется при подключении. `IncludedApplications`, повторная секция Interface и параметры приложений в Peer отклоняются до записи профиля. Исходный профиль сохраняется без подмены пользовательских настроек выбранными исключениями.

## Проверка

Регрессия преобразования профилей воспроизведена на Kotlin 2.2.21: старая реализация падает на комментарии после Interface, исправленная проходит те же исполняемые проверки. Добавлены сценарии комментариев, нескольких Peer, CRLF/CR, замены и очистки исключений, сохранения DNS/AllowedIPs и запрета неподдерживаемых директив.

Flutter-проверки покрывают задержанный первоначальный статус, уже работающий туннель, возврат из фона, неизвестное нативное состояние, доступное отключение и повторное нажатие во время сохранения профиля. Локально успешно выполнены 141 проверка Python и все восемь исполняемых наборов Kotlin 2.2.21. Результаты Flutter, полной Android-сборки и точный источник APK будут добавлены после CI.

## Границы

Изменения не включают автоматическое переподключение, kill switch или запуск после перезагрузки телефона. Никакие сетевые проверки не подменяют явное нажатие подключения. Внешний доступ в Интернет не выводится из одного факта включения локального туннеля.

Удалённое приложение, оставшееся в исключениях, всё ещё может помешать подключению. Список не очищается автоматически и не фильтруется по launcher-приложениям. Следующая доработка — понятное определение этой причины без потери сохранённого выбора.

На физическом Android остаётся подтвердить обновление с сохранением данных, действительное WireGuard-соединение, DNS, IPv4/IPv6, прямой трафик выбранных приложений и поведение при смене сети. Ранее замеченное предупреждение Play Protect и обращение в Google остаются отдельной открытой задачей.

## Приёмка на устройстве

1. Обновить опубликованную версию без удаления приложения; проверить профили и исключения.
2. Открыть приложение при включённом туннеле: дождаться статуса и отключить его одной кнопкой, без промежуточного повторного подключения.
3. Свернуть и снова открыть приложение; повторить с пересозданием Activity. Проверить статус и время текущего сеанса.
4. Без сохранённого профиля дождаться статуса, нажать подключение и убедиться, что открывается редактор «Сохранить и подключить».
5. Импортировать рабочий тестовый профиль с комментариями после заголовков, выбрать установленное приложение для прямого трафика и проверить реальное подключение.
6. При ошибке чтения состояния проверить доступность отключения последнего известного включённого туннеля; после уточнения выключенного состояния новое подключение требует явного нажатия.
