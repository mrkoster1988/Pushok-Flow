# Pushok Flow v0.61.0 — точные ошибки связки Shop

**Статус документа:** проект релиза; APK и GitHub Release не считаются
опубликованными до прохождения полного CI, подписи прежним сертификатом и
проверки публичного манифеста обновлений.

## Исправление по Android-скриншоту 25.11.2026

В версии v0.60 сообщение «Подключение уже привязано к другому телефону»
появлялось для любого HTTP 409 от Shop, в том числе если одноразовый MTProxy
билет был уже использован или обнаружен конфликт привязки идентичностей.

Нативный мост Android теперь читает **только фиксированный структурированный**
код ошибки из ограниченного HTTPS JSON, до 1024 байт, без отображения
произвольных строк и без передачи секретов в Flutter. Новый Flow различает:

- `SHOP_DEVICE_BOUND`: настоящая привязка другого клиента, требуется
  подтверждённый серверный перевыпуск; один private key нельзя переносить
  на второй телефон;
- `SHOP_PROOF_REPLAY`: повторно использованный билет; нажать «Получить
  конфиг» снова для нового 60-секундного подтверждения;
- `SHOP_IDENTITY_CONFLICT`: конфликт аккаунтов Telegram/MTProxy и Shop,
  нужна проверка в админке Shop;
- `SHOP_CONFLICT`: неизвестный 409 — не делать ложный вывод про телефон.

Точный ограниченный список прежних строк Shop также распознаётся при
переходном развёртывании; неизвестный текст не показан пользователю.

## Сохраняется

Единый главный экран, объёмный фон, анимация котёнка, прямые маршруты
рекомендуемых приложений, ручные WireGuard/VLESS профили, нативный Keystore,
подключение только по действию пользователя, сохранённый client_id,
автоматическое обновление APK и подпись прежним постоянным ключом.

## Важные границы

Это **не выпуск peer** и не исправление самого WGDashboard. Для
автоматической выдачи нужен обновлённый Shop с проверенной привязкой
пользователя, включённой политикой, защищённым API WGDashboard, реально
созданным и действующим peer. Изменения backend Shop подготовлены в
v0.061 отдельно. Коммит приложения не выполняет их развёртывание на VPS.

При необходимости пользователь может получить персональный `.conf`
непосредственно из WGDashboard и импортировать его через «Добавить сервер»;
нельзя публиковать конфигурацию/QR с приватным ключом.

## Порядок выпуска

1. Успешные Python, Flutter и Kotlin contract checks точного source SHA.
2. Успешная универсальная Android release candidate и debug CI.
3. Подпись прежним сертификатом `shop.pushok.flow`
   (`8b4114881116a920c3351b503052ac27078fdbbfcae1ace27f1af8245ebb7047`);
   проверка APK v2/v3, versionCode 61, zipalign, ABI и SHA-256.
4. Публичный GitHub Release v0.61.0 с одним универсальным APK и
   `update.json`; проверка канала обновлений анонимным клиентом.
5. Физический Android: обновление поверх v0.60 без потери ключей и
   маршрутов; отличить реальную ошибку Shop от повтора билета,
   отдельно проверить WireGuard handshake и доступ в интернет.
