# Пассивная диагностика сетевой нагрузки

`tools/network_baseline.py` помогает собрать исходные данные перед изменением
MTU, размера буферов, очередей или тарифа VPS. Он читает агрегированные счётчики
Linux дважды и выводит JSON. Python 3.10+; сторонние пакеты и права root обычно
не нужны. Скрипт следует запускать на исследуемом узле.

```bash
python3 tools/network_baseline.py --sample-seconds 5
python3 tools/network_baseline.py --interface ens3 --sample-seconds 10
```

Без `--interface` выводятся наблюдаемые интерфейсы, кроме `lo`. Интервал можно
задать от 0,1 до 30 секунд; по умолчанию — 3 секунды. Для расчёта Mbps берётся
фактически прошедшее монотонное время, доступное в `elapsed_seconds`.

## Что содержит результат

| Поле | Значение |
| --- | --- |
| `cpu.busy_percent` | Доля CPU-времени, выполнявшего работу; idle, iowait и steal исключены |
| `cpu.idle_percent`, `iowait_percent`, `steal_percent` | Отдельные доли простоя, ожидания I/O и времени, отданного гипервизором другим задачам |
| `cpu.softirq_percent` | Доля времени обработки softirq; уже включена в busy, повторно не суммировать |
| `interfaces.<name>.rx_mbps`, `tx_mbps` | Наблюдаемый входящий/исходящий поток в десятичных Мбит/с |
| `interfaces.<name>.deltas` | Изменение счётчиков байтов, ошибок и отброшенных пакетов |
| `interfaces.<name>.mtu_bytes` | MTU интерфейса из sysfs; это не измеренный MTU всего пути |
| `udp4.deltas`, `udp6.deltas` | Прирост `InErrors`, `RcvbufErrors`, `SndbufErrors` в текущем сетевом namespace |
| `status` | `ok` при доступных результатах; `partial` при отсутствии или недостоверности части измерений |

Скрипт исключает повторное прибавление `guest`/`guest_nice`: Linux уже включает
их в `user`/`nice`. При уменьшении счётчика результат за этот интервал считается
неизвестным (`counter_reset`, `null`), в том числе когда уменьшается `iowait`.
При смене sysfs `ifindex` интерфейс считается пересозданным, даже если новые
счётчики больше прежних. Если sysfs недоступен, такое пересоздание обнаружить
по одному только имени нельзя.

## Как интерпретировать

- Mbps показывает **нагрузку за выбранный интервал**, а не доступную скорость
  интернета и не скорость отдельного пользователя. Нулевой поток на незанятом
  сервере ничего не говорит о его предельной пропускной способности.
- Не складывайте поток `wg0`, Docker bridge и физического интерфейса: один
  пакет может учитываться на нескольких из них. RX/TX также нужно сравнивать
  отдельно.
- Рост `RcvbufErrors` или `SndbufErrors` — повод искать переполнение UDP-буферов.
  `InErrors` может включать ошибки других показанных категорий; их нельзя
  безусловно складывать. Большие буферы без измерений не гарантируют улучшение.
- CPU — среднее по всем процессорам. Оно может скрывать перегрузку одного ядра;
  для такого случая нужен отдельный анализ по ядрам и процессам. Высокий steal
  при медленной передаче — повод проверить конкуренцию за vCPU у хостинга.
- При запуске в контейнере сетевые счётчики относятся к его network namespace,
  а `/proc/stat` может описывать CPU хоста. Скрипт не считает это нагрузкой
  конкретного контейнера и не вычисляет процент доступного ему CPU quota.
- Сравнивайте несколько снимков при одинаковой нагрузке. Подтверждение скорости
  требует отдельного теста передачи данных, включая независимый сервер за
  WireGuard-шлюзом. Этот инструмент нагрузку не создаёт.

Системные параметры, сеть и файлы не изменяются. Сетевых запросов нет.
Ключи WireGuard, конфигурации пиров, адреса серверов, DNS-имена, аккаунты,
подписки и переменные окружения не читаются и не попадают в JSON. Названия
интерфейсов и агрегированная нагрузка предназначены для администратора.

Источники по смыслу счётчиков:
[Linux /proc](https://docs.kernel.org/filesystems/proc.html),
[Linux interface statistics](https://docs.kernel.org/networking/statistics.html),
[Linux SNMP counters](https://docs.kernel.org/networking/snmp_counter.html).

Проверка CLI в среде разработки подтверждает работу инструмента в этой среде.
Она не является измерением VPS Pushok или приёмкой скорости на телефоне.
