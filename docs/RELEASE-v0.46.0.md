# Pushok Flow v0.46.0 — отмена сетевых запросов и точный статус подключения

## Состояние

Универсальный APK для Android собран и подписан постоянным ключом; оба CI точного исходного коммита завершились успешно. Публичный выпуск пока не запускался. [Проверка перед публикацией](release-checks/v0.46.0-prepublication-check.json).

## Подписки и вход при зависшей сети

Воспроизведены зависания, которые обычные `connectTimeout` и `readTimeout` не ограничивали: системное определение адреса, получение HTTP-заголовков или потока записи, а также сам `disconnect()`. В этих случаях последовательная очередь подписок или аккаунта могла ждать бесконечно; отмена и последующие действия оставались за старым запросом.

Ожидание транспорта теперь отделено от последовательной обработки состояния. Общий бюджет подписки составляет 40 секунд, одной команды аккаунта — 20 секунд, включая её последовательные HTTP-обмены. Отмена будит ожидающую операцию; поздний ответ не применяется. Вызов отмены не ждёт завершения системного `disconnect()` на потоке интерфейса.

Для каждой функции используются два транспортных потока; количество незавершённых операций, включая допущенные в очередь, ограничено двумя. Если системный вызов игнорирует прерывание, он продолжает занимать свой слот до фактического выхода. Повторные нажатия не создают неограниченные потоки или очередь; при занятых слотах возвращается фиксированная ошибка сети. Следующий обмен одной команды допускается сразу после завершения предыдущего, без ложного отказа из-за завершающегося рабочего потока. Это ограничение ожидания и ресурсов приложения, а не обещание мгновенного прекращения любого системного вызова.

Отмена относится к конкретному запросу и его соединению. Старая задача не отключает новую. Результат подписки, полученный после отмены, удаляется; перед записью тела запроса авторизации повторно проверяется актуальность операции. Секреты и подробности системных исключений не попадают в сообщения интерфейса. Сохранение профилей, решения аккаунта и защищённая запись остаются в прежних последовательных обработчиках.

## VLESS: DNS и запоздавшие ответы состояния

В адресе системного DNS сохраняется область IPv6 (`%7`, `%wlan0` и другие значения, полученные от Android). Ранее этот суффикс удалялся, поэтому локальный IPv6 DNS терял указание интерфейса назначения. Формирование адресов IPv4, глобального IPv6 и прежний резервный адрес сохраняются.

Ответы сервиса Xray проверяются перед доставкой в интерфейс. Запоздавший ответ предыдущего состояния не должен подтверждать включённое подключение после отключения и не должен завершать новый сеанс. Для такого ответа используется состояние «не удалось определить», после которого приложение перечитывает текущий статус.

23.11.2026 в 04:17–04:18 МСК на `pushok.shop` обнаружена установленная **MTProxy v1.122**. API Flow отвечает совместимым протоколом 1, а запрос профиля без сессии получает ожидаемый HTTP 401. Вход использует существующий `@mtproxy_pushok_bot`. [Контракт и текущее состояние](ACCOUNT.md).

## Границы проверки

Локально прошли 267 тестов Python, 311 тестов Flutter и 24 исполняемых набора Kotlin; анализатор Flutter не обнаружил замечаний. Новый транспорт аккаунта проверен в восьми группах, включая последовательный вход при одном зависшем рабочем потоке. Проверки подписок воспроизводят зависания DNS, открытия соединения, заголовков, чтения и закрытия, отмену, удаление позднего результата и ограничение числа операций.

Регрессии используют управляемые зависания и отложенные ответы без реального Telegram, пользовательских профилей и внешнего DNS. Эти проверки не заменяют обязательные CI точного исходного коммита и Android-сборку; результаты выпуска добавляются после их завершения.

На физическом телефоне остаются исходный QR пользователя, полный вход через Telegram, разрешение Android, работа серверного подключения и смена сети. Для VLESS выбор начального DNS пока выполняется при включении: если после перехода с Wi-Fi на мобильную сеть прежний локальный DNS недоступен, требуется отключить и снова включить подключение. Безопасное обновление DNS работающего ядра в этот выпуск не входит; версия ядра и режимы маршрутизации не меняются.
