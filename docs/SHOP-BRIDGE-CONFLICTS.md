# Pushok Flow: точная диагностика отказа Shop

Исправление по Android-скриншоту Pushok Flow 0.60: успешный MTProxy-вход,
но на «Получить конфиг» отображается «Подключение уже привязано к другому
телефону». В 0.60 **все HTTP 409** от Shop отображались этой фразой,
даже если настоящий ответ: «Подтверждение уже использовано» или
«Для аккаунта требуется проверка привязки».

В следующей версии используется ограниченный JSON-код из ответа Shop
`/shop/api/flow/bridge/exchange`:

| Код Shop | Экран Flow | Следующее действие |
| --- | --- | --- |
| FLOW_DEVICE_BOUND | SHOP_DEVICE_BOUND | Проверить привязку в Shop, не копировать WG private key на другой телефон |
| FLOW_PROOF_REPLAY | SHOP_PROOF_REPLAY | Запросить свежий билет, повторно нажав «Получить конфиг» |
| FLOW_IDENTITY_CONFLICT | SHOP_IDENTITY_CONFLICT | Проверить Telegram ID и идентичность аккаунта в Shop |
| неизвестный HTTP 409 | SHOP_CONFLICT | Показать общий конфликт, не утверждать, что виноват другой телефон |

Android читает только HTTPS JSON `detail`, до 1024 байт, без редиректов,
не доверяет неизвестным полям и **не выводит произвольные сообщения
сервера**. Для старых релизов Shop распознаются только точные ранее
заданные фразы.

Это исправляет диагностику **в новых APK**, но само не создаёт WireGuard
peer и не переносит подписки. Для работоспособного канала нужны проверенные
WGDashboard, права на Shop, установленный Shop с механизмом перевыпуска и
приёмка на физическом Android.

Временное подключение без Shop: создать отдельный peer для этого телефона
в WGDashboard, скачать его собственный `.conf` и импортировать через
«Добавить сервер» в Flow. Конфигурация с private key не должна появляться
в чате, тикетах или публичных скриншотах.
