# Pushok Flow 0.60.0 — одна главная, остальные функции в настройках

## Главная

- Крупная круглая кнопка **Подключить / Отключить** с существующей проверкой нативного состояния WireGuard/VLESS.
- Под кнопкой — **Войти через Telegram** (если аккаунт MTProxy не подключён) и **Получить мой конфиг** (после успешного входа). Прежняя нативная связка MTProxy → Shop, ограничение токенов и Android Keystore сохранены.
- При ожидающем подтверждении показывается прежний безопасный код и кнопка открытия Telegram; отмена и восстановление входа не удалены.
- Далее компактные показатели **дата окончания подписки**, **сколько осталось**, **передача данных**, **свежесть WireGuard handshake** и **отклик сети в мс**.
- Отклик измеряется как **TCP-подключение к pushok.shop:443**, поэтому подписан «Отклик сети», а не заявлен ICMP-ping WG узла. До подтверждения соединения или при ошибке показывает «—»/«Нет ответа», **без выдуманных цифр**. Проверка выполняется только на переднем плане и когда туннель подтверждён, раз в 45 секунд, без передачи ключей.
- Срок берётся из сохранённой управляемой WireGuard-подписки Flow. Ручные конфиги не выдают себя за бесплатную подписку.

## Настройки ⚙️

Вместо пяти нижних вкладок **только главная** и одна шестерёнка сверху. Первый пункт — **Справка** с порядком действий (войти → получить конфиг → подключиться). Далее Аккаунт, Серверы и подписки, Маршруты и исключения, Pushok ИИ, Версия и обновления, Диагностика. У каждого подраздела есть понятный возврат к настройкам и главной.

Полный аккаунт с автоматическим получением, ручные WireGuard/VLESS, настройка split tunneling, обновления, диагностика и функции Pushok ИИ остаются доступны. UI не меняет API Shop/MTProxy, полномочия, данные, серверные ключи, миграции и способы оплаты.

## Проверки и границы

- Flutter UI-тесты: одна главная, первые настройки — справка, возврат, сохранение старых сценариев маршрутов/подписок/туннеля, проверка значения отклика.
- Android CI должен подтвердить типы, сборку, сертификат подписи и регрессии перед публичным выпуском. Реальное подключение и обновление поверх установленной версии 0.59 остаются для проверки на устройстве.
- Новый APK **нельзя** объявлять опубликованным, пока GitHub Release не содержит подписанный файл и `update.json`. Не выдавать кандидат с временной подписью за официальный APK.
