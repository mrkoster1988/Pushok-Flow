# Pushok Flow v0.60.0 — единая главная и доступ через Shop

> **Статус:** исходники-кандидат. Это не опубликованный Android-релиз.
> Нельзя распространять CI debug APK или временно подписанный release candidate
> как официальное обновление. Публичная установка требует прежнего
> постоянного сертификата и проверенного update.json.

## Новый главный экран

- Один главный экран: анимированный Пушок, крупная кнопка подключения и две
  последовательные команды — «Войти через Telegram» и «Получить конфиг».
- Telegram-вход использует существующее подтверждение MTProxy, а выдача личного
  WireGuard идёт через авторизованную нативную интеграцию Shop.
- Кнопка получения выполняет **разовый** запрос без включения фоновой
  синхронизации, когда пользователь ранее выключил её.
- Под кнопками показываются подтверждённый статус туннеля, срок выбранной
  управляемой подписки, фактический объём переданного трафика и время последнего
  WireGuard handshake при наличии свежих данных. Непроверенные значения не
  подставляются.
- Значение «Пинг» остаётся «Нет замера», пока не будет реализовано честное
  измерение RTT; handshake не является пингом.
- Действительно истёкший доступ и отозванный доступ различаются.

## Настройки

Нижнее меню из пяти разделов убрано. Шестерёнка открывает «Настройки»; первым
пунктом идёт «Справка», далее «Маршруты», «Серверы и подписки», «Аккаунт и
обновления», «Pushok ИИ». Сохранены импорт QR/файлов, выбор профиля,
split tunneling, проверка обновлений и диагностика.

## Что не меняется

Android WireGuard и Xray, штатный запрос разрешения Android, безопасное
хранение через Android Keystore, привязка личной подписки к устройству,
защита от повторных подключений, прежние профили и исключения. Эти изменения
не переносили пользователей, peer, платежи и серверные настройки WGDashboard.
Существующий объёмный анимированный фон в основной ветке должен сохраняться
после слияния.

## Проверка перед выпуском

1. Успешные Source contract checks (Flutter, Python, статический анализ).
2. Успешные Android debug и universal release candidate, включая проверки
   Kotlin, QR, маршрутизации, состава ABI и Android Manifest.
3. Постоянная подпись `shop.pushok.flow` прежним сертификатом; проверка
   package/versionCode, SHA-256, APK v2/v3 и zipalign.
4. Публикация подписанного APK и `update.json` в GitHub Releases с последующей
   независимой загрузкой по публичной ссылке.
5. Физический Android: обновление поверх v0.59 без потери ключей и маршрутов,
   вход MTProxy, личная подписка, реальный peer в WGDashboard, handshake,
   интернет, отключение и последующий отзыв. До этого сервисную интеграцию
   нельзя объявлять доказанно исправленной.

**Важно:** если WGDashboard доступен только по публичному HTTP IP, это ещё
не безопасный API-канал для Shop. Надо обеспечить HTTPS с доверенным
сертификатом или защищённое соединение и подтвердить запись peer. Старые
подписки автоматически не переводятся на новый сервер.
