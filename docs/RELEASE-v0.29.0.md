# Pushok Flow 0.29.0 — поиск и управление исключениями

## Изменения

В разделе «Маршруты» добавлены поиск по названию приложения и package ID без учёта регистра, фильтры «Все»/«Выбранные», счётчик сохранённых исключений, обновление списка и снятие всех исключений с подтверждением. Поиск и фильтр сохраняются при переходе между вкладками и обновлении данных. Список строит строки по мере прокрутки, чтобы не создавать тысячи виджетов одновременно.

Выбранные package ID, отсутствующие в результате launcher-запроса Android, остаются видимыми с пояснением «Нет в списке приложений». Их можно убрать по одному либо общей очисткой. Отсутствие в этом списке не доказывает удаление приложения; приложение может не иметь доступной launcher activity. Выпуск не заявляет автоматическое игнорирование действительно удалённых пакетов при установке туннеля.

Главная остаётся упрощённой согласно предыдущей просьбе пользователя. Настройка профилей находится в «Серверах», исключений — в «Маршрутах».

## Сохранение и ошибки

Изменение переключателя не считается сохранённым до подтверждения Android. Запись сравнивает ожидаемый список с текущим, поэтому конкурирующая Activity не может незаметно перезаписать более новый выбор. При конфликте перечитывается действительный список. Запоздалый ответ после переключения приложения не восстанавливает старый выбор и не снимает индикатор нового чтения.

Очистка требует подтверждения; подтверждение из прошлого сеанса активности не очищает список после переключения приложения. Во время записи заблокированы другие изменения, подключение и редактирование профиля. Проверка native-состояния туннеля и запись выполняются под общим токеном операций, поэтому подключение не может вклиниться между проверкой и записью. Неизвестное состояние туннеля запрещает изменение.

При ошибке чтения показываются последние подтверждённые данные с ошибкой, а не пустой список. Если `SharedPreferences.commit()` возвращает ошибку или исключение, память Android уже может содержать неподтверждённый набор; общий для процесса флаг запрещает дальнейшее чтение/запись и подключение с ним до перезапуска приложения. Сами исключения остаются в прежнем local SharedPreferences; новый формат хранения не вводится.

Запрос списка приложений перенесён в IO-поток. Названия нормализуются до одной строки без управляющих символов, результаты и аргументы строго проверяются, исходные сообщения ошибок платформы не попадают в интерфейс. Новые разрешения и зависимости не добавлены.

## Проверки

Локально прошли 133 Python-теста. Добавлены проверки интерфейса и платформенного контракта, интеграционные сценарии сохранения/ошибок/переключения приложения и седьмой исполняемый Kotlin-набор для условной записи, отказа хранилища и нормализации названий. Flutter, Kotlin и Android build выполняются в CI; результаты точного коммита будут внесены после завершения.

## Проверка на телефоне

После обновления без удаления приложения проверить сохранение профилей и прежних исключений. Найти приложение по названию и package ID, переключить фильтр «Выбранные», снять одно исключение, отменить и подтвердить очистку. Проверить отказ редактирования при работающем туннеле, затем после отключения и повторного подключения проверить фактический прямой трафик выбранного приложения.

Реальный WireGuard-туннель, DNS/IPv4/IPv6, маршруты конкретного устройства и обновление поверх установленной версии требуют испытания на телефоне. Ранее наблюдавшееся предупреждение Play Protect остаётся отдельным неразрешённым вопросом; выпуск не заявляет его устранение.
