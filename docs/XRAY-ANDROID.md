# Xray в Pushok Flow

## Закреплённый движок

Приложение включает неизменённый официальный **libXray v26.11.9**, API оболочки 3.
Оболочка: `5a0f7d8d1c28b34afb5727b04b26a10f6dbac7e3` (MIT).
Xray-core: `676eaf66f8f05d4d558ee7a74b4736623d3feeb9` (MPL-2.0).

Официальный архив: https://github.com/XTLS/libXray/releases/download/v26.11.9/libxray-android.zip

- ZIP: 52 573 017 байт, SHA-256 `1b1aa12124a7112af983a6cea74c77f27aadc6b650acf3c5a57019619ba9fa48`.
- AAR: 53 228 649 байт, SHA-256 `4ddb0608ffee6e642ab9cda056c37df0b420a6b1e2be7292de33a1a3f3ca7a9a`.
- Сборка upstream: Go 1.27.3, NDK r30, минимальный Android API 21.
- Все четыре библиотеки upstream имеют `PT_LOAD` с выравниванием 16 KiB.

`python3 tools/fetch_xray_android.py` получает архив только при сборке приложения,
проверяет оба размера и SHA-256, ELF-сегменты каждой ABI и записывает один
заранее известный AAR в сгенерированный проект. На телефоне движок не скачивается.
Кэш с неправильным хешем не используется. Лицензии и точные адреса исходников
включены в `assets/licenses/` APK; архив исходников доступен в upstream.

## Изоляция и подключение

WireGuard и Xray содержат разные Go runtime. Поэтому `XrayVpnService` работает
в отдельном процессе `:xray`; основной процесс не импортирует libXray.
Сервис не экспортируется, защищён `BIND_VPN_SERVICE`. IPC дополнительно проверяет
UID отправителя. Ссылка/JSON передаются через закрытый Messenger, не через Intent,
уведомления, дисковые временные файлы или логи.

Пассивная проверка состояния может создать пустой Java-сервис через
`BIND_AUTO_CREATE`. Она не загружает Go, не запускает foreground-уведомление,
не создаёт TUN и не выполняет подключение. Без `AUTO_CREATE` Android может вернуть
успех bind, но не вызвать callback для отсутствующего сервиса.

Явное подключение после согласия Android создаёт foreground-сервис и TUN с IPv4,
IPv6 и маршрутами `0.0.0.0/0`, `::/0`. Исключения передаются системному
`addDisallowedApplication` до `establish`; недоступное выбранное приложение
прерывает подключение. Приложение не исключает собственный UID автоматически.

JSON содержит единственный TUN inbound и единственный VLESS outbound. Прямого
fallback нет. Поддерживается RAW/TCP с TLS или REALITY, с необязательным Vision.
Сертификат TLS проверяет ядро; параметры отключения проверки запрещены импортом.
DNS приложений (`1.1.1.1`, `1.0.0.1`) проходит через TUN и VLESS. Разрешение имени
самого сервера выполняет защищённый bootstrap-резолвер: DNS текущей физической
сети, резервный адрес — `1.1.1.1:53`.

TCP/UDP сокеты ядра и bootstrap DNS вызывают `VpnService.protect`.
Контроллеры регистрируются один раз на процесс: Xray добавляет их в общий список,
поэтому callback обращается к текущему владельцу сервиса, а не сохраняет старый.
Внутренний JSON содержит `env: {"xray.tun.fd": "…"}`. Xray дублирует descriptor;
приложение сохраняет исходный `ParcelFileDescriptor` и закрывает его только в
последовательной очереди после `stopXray`.

Начало, остановка и очистка всех экземпляров сервиса используют одну очередь
процесса. Просроченное или отменённое начало не может позднее опубликовать UP.
Если нативная остановка не завершилась, состояние остаётся неизвестным; через
две секунды watchdog завершает только изолированный процесс `:xray`, освобождая
все его копии descriptor. Сервис не восстанавливает соединение автоматически
после остановки системой, перезапуска или старого Intent.

## Проверки и границы

- JVM: разбор ссылок, JSON TLS/REALITY, отсутствующий прямой fallback, границы
  срока операции, параллельная отмена, устаревшее поколение, неизвестное состояние
  до подтверждённого завершения native.
- Python: manifest isolation, разрешения foreground-сервиса, размеры/хеши,
  16 KiB ELF и лицензии внутри APK.
- Официальный Linux libXray той же версии: `testXray` на сгенерированном JSON
  TLS/REALITY с Vision и без него; ошибочный протокол отклоняется. `testXray` не
  устанавливает TUN и не проверяет доступность сервера.

Состояние «Туннель включён» подтверждает локальный TUN/ядро. Оно не означает
успешное удалённое рукопожатие. Живой профиль, DNS, IPv4/IPv6, исключения,
переключение Wi-Fi/мобильной сети и повторное подключение необходимо проверить
на телефоне; этот документ не заявляет пройденную проверку устройства.
