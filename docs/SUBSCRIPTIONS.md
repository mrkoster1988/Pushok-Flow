# Подписка Pushok в Flow

## Существующий аккаунт MTProxy

Регистрация уже реализована в **MTProxy Pushok**. В v0.43.0 действие **«Открыть кабинет MTProxy»** сначала открывает [@mtproxy_pushok_bot](https://t.me/mtproxy_pushok_bot) в установленном Telegram. Если подходящего приложения нет либо Android не разрешает переход, открывается [веб-кабинет](https://pushok.shop/). В боте кабинет доступен через его меню. Повторная регистрация пользователя с тем же Telegram ID не создаёт вторую учётную запись.

Имя действующего бота сверено через публичную конфигурацию сервера, а не только по примеру настроек: [результат проверки](development-checks/mtproxy-account-v043.json). **[@pushok_app](https://t.me/pushok_app)** остаётся общей ссылкой экосистемы и отдельной кнопкой в профиле Flow. Ранее текст карточки ошибочно обещал регистрацию, оплату и подписки по этой ссылке; это утверждение удалено.

Вход в кабинет и настройки подключения Flow — разные операции. Начиная с v0.44.0 действие **«Войти через Telegram»** позволяет подтвердить код в существующем кабинете и выдать Flow отдельную сессию только для чтения профиля и баланса. Сама сессия кабинета в APK не передаётся. Требуется совместимый API MTProxy v1.121; полный набор исправлений кабинета для v0.45.0 требует установки v1.122. [Сценарий входа и текущее состояние сервера](ACCOUNT.md). Новая регистрация не создаётся. Наличие аккаунта MTProxy не означает наличие платной VLESS/WireGuard-подписки. Серверы Flow получает по персональной HTTPS-ссылке своего провайдера или панели.

## Как добавить серверы

1. Получите персональную HTTPS-ссылку подписки у своего провайдера: обычный VLESS-список или управляемый WireGuard в формате Flow v1.
2. Откройте **Серверы → Подписки → Добавить подписку**. Используйте **Вставить**, **Сканировать QR** или **QR из фото**, затем подтвердите добавление.
3. Если ваш магазин поддерживает **«Открыть в Pushok Flow»**, можно использовать эту кнопку: приложение покажет защищённую форму с источником серверов и запросит подтверждение импорта.
4. Выберите сервер и включите подключение на главной. Импорт сам по себе не включает соединение и сохраняет прежний выбранный профиль, если он уже есть. Начиная с v0.54.0 строка **«Выбранный сервер»** на главной показывает выбор; нажатие открывает список серверов. Во время проверки каталога или после ошибки чтения неподтверждённое имя не отображается.

Поддержка перехода из Shop VPN есть в его исходниках; работающий магазин, оплата и выдача подписки требуют отдельной проверки. Существующая регистрация MTProxy не подтверждает эти функции магазина.

Поддерживается и совместимая ссылка из собственной панели 3x-ui. Нужна именно ссылка подписки HTTPS; отдельный `vless://` по-прежнему добавляется обычным редактором профиля.

В v0.45.0 HTTPS-ссылку подписки также можно импортировать из QR камерой или из фото. После распознавания нажмите **«Добавить как подписку»**, проверьте название и подтвердите **«Добавить подписку»**. До этого подтверждения сетевой запрос не начинается. Исходный черновик профиля сохраняется при возврате; успешное добавление открывает список серверов и само не включает VPN.

Начиная с v0.56.0 доступен и обратный переход: если в форме добавления
подписки камера или фото вернули отдельный VLESS- или WireGuard-профиль,
нажмите **«Добавить как профиль»**. Повторно сканировать QR не нужно.
Проверьте название и отдельно нажмите **«Сохранить профиль»**. Для вставленного
или введённого отдельного подключения предлагается тот же редактор;
окончательную совместимость проверяет обычное сохранение профиля.

Кнопка возврата открывает прежнюю форму подписки с её URL и названием.
Данные профиля остаются скрытыми, оба редактора используют одну защиту экрана.
Отменить предложенный импорт можно до открытия редактора; новая вставка или
редактирование отменяют старое предложение. Создаётся новый ручной профиль;
существующий выбранный сервер сохраняется, соединение включается отдельно.
При ошибке сохранения черновик остаётся в редакторе для повторной попытки.

## Обновление и срок

Начиная с v0.57.0 Flow принимает [управляемую WireGuard-подписку v1](MANAGED-WIREGUARD-SUBSCRIPTIONS.md).
Она предназначена для связки Shop и отдельного WGDashboard; Shop должен
выдавать согласованный JSON по персональной HTTPS-ссылке устройства.
Ссылка панели, её административный API и URL обычного `.conf` этот контракт
не заменяют. Совместимая серверная выдача и реальный туннель проверяются отдельно.

Состояния WireGuard-подписки — активна, срок истёк и доступ отозван.
Подтверждённый ответ `expired` или `revoked` удаляет только её серверы,
сохраняя карточку для последующего обновления. Истёкший локально срок
блокирует новое подключение; уже работающий туннель эта версия по таймеру
не отключает. Ограничение peer на сервере остаётся обязательным.
Продление сохраняет выбор сервера, если провайдер сохраняет его стабильный
идентификатор и увеличивает ревизию ответа.

Flow сохраняет до пяти подписок в общем лимите двадцати профилей. Серверы из подписки отмечены её названием. Обновление заменяет только серверы этой подписки; ручные профили и другие подписки сохраняются. Существующий выбранный сервер остаётся выбранным, пока его конфигурация присутствует в новом списке.

Автоматическое обновление серверов проверяется при открытии приложения и возвращении в него: не чаще одного раза в шесть часов после успеха и одного раза в час после неудачной попытки. Это отдельная настройка от фоновой загрузки обновлений самого приложения. При закрытом Flow эта версия не запускает отдельного фонового задания обновления подписок.

Для изменения списка серверов собственное подключение Flow должно быть отключено. Сетевой запрос не удерживает блокировку туннеля; перед сохранением приложение повторно проверяет его состояние. Ошибка сети, неверный ответ или конфликт не стирают прежний список.

Для обычной VLESS-подписки срок и счётчики берутся из заголовка `Subscription-Userinfo` и остаются информационными. Если сервис их не передал, приложение показывает отсутствие данных. Для управляемого WireGuard срок обязателен в самом JSON. Flow не подтверждает оплату и не продлевает подписку локально. Доступ ограничивается сервером провайдера.

Удаление подписки требует подтверждения и удаляет только её серверы с этого устройства. Оно не отменяет оплату или подписку в магазине. Продление и управление оплатой выполняются у провайдера, выдавшего ссылку.

## Как сообщить об ошибке

Начиная с v0.55.0 у ошибки в форме добавления, карточке подписки или общем
списке есть **«Скопировать ошибку»**. Нажмите её и вставьте полученный текст
в обращение. Отчёт содержит версию Flow, действие, источник и фиксированное
описание причины. Личная ссылка, домен, названия и ID, конфигурации и ключи
в него не включаются. Автоматической отправки нет.

При изменении ссылки, новой попытке или успешном обновлении старое сообщение
исчезает. Если запись в буфер не удалась, кнопка позволяет повторить её.
Для восстановленной ошибки обновления отчёт не угадывает, когда и каким
способом началась исходная загрузка. Неизвестные коды показываются как
`SUBSCRIPTION_UNAVAILABLE`; сообщения провайдера и содержимое ответа не копируются.

## Формат и ограничения

- HTTPS, до трёх перенаправлений также на HTTPS; ответ не более 512 КиБ.
- WireGuard: строгий JSON `pushok-flow-subscription` версии 1 со сроком, ревизией и стабильными идентификаторами. Полные правила и поведение явного пустого списка `expired`/`revoked` описаны в [контракте](MANAGED-WIREGUARD-SUBSCRIPTIONS.md).
- UTF-8 список ссылок по одной на строку или его Base64-представление. В ответе допускается до 200 непустых записей; одновременно сохраняются не более 20 совместимых серверов в общем лимите профилей устройства. Больший список не обрезается молча.
- Применяются существующие ограничения VLESS: TCP с TLS или REALITY, WebSocket и gRPC с TLS. Начиная с v0.54.0 распознанные несовместимые записи в смешанном ответе пропускаются: ссылки `vmess://`, `trojan://`, `ss://`, `ssr://`, `hysteria://`, `hysteria2://`, `hy2://`, `tuic://`, `wireguard://` и VLESS с явно неподдерживаемыми параметрами. Их протоколы не становятся поддерживаемыми; настройки таких записей не преобразуются и не упрощаются.
- Количество пропущенных несовместимых записей сохраняется и отображается в карточке подписки. Следующее полностью совместимое обновление убирает это предупреждение. Подписки, сохранённые предыдущими версиями, читаются со счётчиком 0 до следующего обновления.
- Для обычного VLESS-списка отсутствие совместимых серверов, повреждённая ссылка, неизвестный формат, повтор одинакового эффективного подключения или превышение лимитов отклоняют ответ целиком. При обновлении прежние серверы сохраняются. Пустой VLESS-список не заменяет рабочие настройки.
- URL с логином/паролем, fragment, локальным адресом или приватным IP не принимается. Адреса DNS проверяются перед запросом.
- QR для отдельного WireGuard/VLESS открывает обычный редактор профиля. В v0.45.0 HTTPS-подписка из QR или текстового файла открывает предложение добавить подписку; канонический `pushokflow://subscription?...` проходит тот же существующий обработчик внешних подписок.

Персональная ссылка даёт доступ к конфигурации: её нельзя публиковать. На устройстве ссылка и серверы находятся в зашифрованном каталоге. В общие метаданные интерфейса передаются название, домен, количество серверов, время и счётчики; секретный URL туда не включается. Поле ввода защищено от снимков экрана и по умолчанию скрыто.

## Переход из магазина

Приложение принимает узкую ссылку `pushokflow://subscription?url=<HTTPS-URL>&name=<название>`. Внешняя ссылка открывает только черновик. Загрузка и сохранение требуют нажатия пользователя в приложении.

Для Telegram Mini App магазин использует промежуточную HTTPS-страницу. URL подписки передаётся в fragment после `#`, не в запросе к веб-серверу. Переход в приложение выполняется явной кнопкой. Пароли панели, токен бота и Telegram ID приложению не нужны.

## Проверка на реальном устройстве

Отдельно требуется подтвердить открытие существующего кабинета MTProxy с телефона, а также путь для серверной подписки: провайдер → действующая ссылка → импорт → реальный трафик → продление → обновление срока. Автоматические тесты формата, хранения и переходов не подтверждают приём платежа, доступность конкретной панели или работоспособность туннеля на телефоне.
