# Аккаунт MTProxy внутри Pushok Flow

## Уточнения v0.49.0: восстановление локального входа

При подтверждённом сбое хранилища аккаунта Flow показывает **«Восстановить вход»**.
Перед действием нужно подтвердить удаление сохранённого входа только на этом
устройстве. После успешного восстановления новый вход через существующий
Telegram запускается отдельным нажатием. Аккаунт и баланс MTProxy, серверы
и подписки не удаляются; запросов к серверу при восстановлении нет.

Обычная ошибка чтения больше не удаляет зашифрованную запись автоматически.
При явном восстановлении сначала подтверждается удаление только записи аккаунта,
затем заменяется только его ключ `pushok_flow_account_v1` и проверяется
шифрование/расшифрование AES-GCM. Ключи профилей и постоянный сертификат подписи
APK не затрагиваются. При любой ошибке хранилище остаётся недоступным для входа,
интерфейс не сообщает об успехе и позволяет повторить восстановление.

Окно подтверждения, открытое до ухода в другое приложение, не сбрасывает
состояние, прочитанное после возвращения. Дополнительная нативная проверка
отклоняет устаревшее восстановление до отмены операций уже здорового аккаунта.
Если старый токен невозможно расшифровать, восстановление не подтверждает
удалённый отзыв сессии: действует прежний серверный срок 12 часов.
Форматы записей v1/v2 и существующий серверный контракт сохраняются.
[Объём и проверки](RELEASE-v0.49.0.md).

## Уточнения v0.48.0: отмена во время ожидания

«Отменить вход» и «Выйти» работают во время ожидающего опроса или обновления профиля. Старые код и данные скрываются сразу; запоздавший ответ не возвращает их. Переход в Telegram для отменённого запроса также блокируется.

Отмена передаёт только показанный публичный код и очищает совпадающий запрос или сессию, уже выданную по этому коду. Поэтому отмена во время ожидания `/me` после получения токена больше не оставляет аккаунт подключённым. Несовпадающая отмена не удаляет другой аккаунт. Локальная запись v2 читает v1 без потери токена, срока или профиля; Keystore и шифрование сохраняются. При неподтверждённой очистке показываются ошибка и повтор, а не ложное сообщение об успешном выходе.

Анонимные ответы `/api/v1/flow/capabilities` и `/api/v1/public-config` проверены повторно **23.11.2026 в 07:57:48–07:57:55 МСК**: протокол 1, прежние права чтения и срок 43 200 секунд, существующий `@mtproxy_pushok_bot`. Эта проверка не создавала код входа или сессию и не подтверждает прохождение полного входа на телефоне. [Сохранённые публичные наблюдения](release-checks/v0.48.0-account-server-check.json). [Изменения и проверки v0.48.0](RELEASE-v0.48.0.md).

## Уточнения v0.45.0 и MTProxy v1.122

В Android код входа и данные истёкшей сессии скрываются по локальному сроку, даже когда следующий опрос отложен из-за HTTP 429. Последний профиль через пять минут получает отметку устаревших данных без лишнего сетевого запроса. При истечении сессии нативное состояние проверяется один раз; сворачивание останавливает таймеры, возврат перечитывает сохранённый статус.

В кабинете v1.122 ответ `/me` привязан к конкретному входу: старый ответ не может показать одного пользователя при токене другого. Перезагрузка и истечение прежней веб-сессии сохраняют только ещё не привязанный публичный код и исходное время получения, не больше пяти минут. Новый вход снова получает действительный профиль, заново проверяет запрос и требует согласия. Явный выход или смена уже привязанного аккаунта сбрасывает запрос.

Если веб-кнопка Telegram не работает, экран запроса предлагает открыть того же `@mtproxy_pushok_bot` с тем же публичным кодом и перейти в существующий Mini App. Это не устраняет настройку домена Login Widget и не подтверждает установку серверного обновления. Совместимость API начинается с v1.121; полный набор этих исправлений требует v1.122.

## Вход

В Android v0.44.0 карточка **Профиль → Аккаунт Pushok → Войти через Telegram** использует существующий аккаунт MTProxy. Отдельной регистрации, базы пользователей или нового бота Flow нет.

1. Flow получает короткий запрос входа и показывает код из 12 символов.
2. Открывается существующий `@mtproxy_pushok_bot`; его кнопка ведёт в кабинет MTProxy. Если Telegram недоступен, используется `https://pushok.shop/?flow=…`.
3. В кабинете пользователь входит прежним способом, проверяет текущий аккаунт и совпадение кода, затем явно разрешает или отклоняет подключение.
4. После возврата в Flow приложение получает отдельную сессию и показывает профиль и баланс. Запрос действует пять минут; сессия — 12 часов.

Для этого сценария на сервере нужен совместимый API `/api/v1/flow` из MTProxy v1.121 и соответствующее обновление кабинета и бота. APK проверяет поддержку протокола. Если сервер ещё не обновлён, показывается понятное сообщение и остаётся кнопка существующего кабинета. Публикация APK сама по себе не доказывает развёртывание серверной части.

## Доступные данные

| Данные | Отображение |
|---|---|
| Имя | Отображаемое имя существующего пользователя MTProxy |
| Роль | Роль кабинета; не даёт дополнительных полномочий приложению |
| Подтверждение телефона | Только признак подтверждения; сам номер не передаётся |
| RUB | Целые копейки преобразуются в рубли с двумя знаками |
| BONUS | Целые минимальные единицы преобразуются с двумя знаками |
| XTR | Целые Telegram Stars |

Отрицательный баланс после возвратов отображается без округления или обнуления. При недоступной сети последнее полученное значение сохраняется и помечается как требующее обновления. Открытие профиля само не начинает авторизацию.

Баланс относится к кабинету MTProxy. Вход не покупает подписку, не добавляет серверы, не меняет маршруты и не запускает туннель. Списание денег, управление рекламой и административные действия не входят в права сессии Flow.

## Разделение сессий

Сессия кабинета остаётся в кабинете. Flow получает отдельный токен с фиксированными правами `profile:read` и `wallet:read`. Сервер отвергает его на обычных и административных API кабинета; сессия кабинета также не заменяет сессию Flow на `/flow/me` и `/flow/logout`.

В Telegram и HTTPS-ссылку попадает только открытый код для сравнения. Секрет запроса и токен доступа не передаются в URL, Flutter, буфер обмена, логи или сообщения об ошибках. Android хранит их с AES-GCM и ключом Android Keystore; резервное копирование данных приложения отключено. Сервер хранит хеши секретов.

Пользователь явно подтверждает запрос в уже авторизованном кабинете. Бот открывает страницу и не выдаёт согласие автоматически. При смене аккаунта или выходе из кабинета незавершённый экран согласия сбрасывается. Код удаляется из видимого URL до обычных авторизованных запросов; страницы кабинета получают `Referrer-Policy: no-referrer`.

Повтор получения токена после потерянного ответа допустим только с тем же секретом в пределах исходного пятиминутного запроса. Он возвращает ту же сессию и не продлевает её. Отозванная сессия и заблокированный пользователь не восстанавливаются повтором. Сервер ограничивает частоту запросов и число активных записей, а переход решения выполняется в транзакции.

## Возврат из Telegram и выход

В ожидании подтверждения Flutter опрашивает нативную часть только на видимом экране. При сворачивании опрос приостанавливается; после возврата перечитывается сохранённое состояние. Нативная часть сохраняет запрос при пересоздании Activity и процесса до истечения срока. Поздний ответ от отменённого входа не может заменить новый аккаунт.

«Выйти» очищает данные этого устройства и отзывает текущую сессию на сервере. Если сеть недоступна, локальный выход всё равно завершается, а интерфейс отдельно сообщает, что серверный отзыв не подтверждён; исходный срок сессии остаётся ограниченным.

## Проверка на телефоне

Испытание реального Telegram, Android Keystore, системного открытия ссылки и сохранения состояния при уничтожении процесса требуется на физическом телефоне. Автоматические проверки моделей, очередей и тестового API не заменяют этот этап. Проверять следует существующий аккаунт: одинаковый код, явное согласие, возврат в Flow, реальные единицы баланса, выход, отказ и истечение запроса.
