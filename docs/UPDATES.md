# Обновления Pushok Flow на Android

Начиная с v0.24.0, в **Профиль → Версия и обновления** можно проверить выпуск, скачать APK и открыть системное подтверждение обновления. Проверка и загрузка запускаются кнопками. Приложение не устанавливает обновления без действия пользователя.

## Порядок для пользователя

1. Нажать **Проверить обновления**.
2. Если доступна новая версия, нажать **Скачать** и дождаться проверки файла.
3. При первом обновлении нажать **Разрешить установку**, разрешить установки из Pushok Flow в настройках Android и вернуться в приложение.
4. Нажать **Установить обновление** и подтвердить действие в системном окне Android.

При обычном обновлении поверх приложения его данные сохраняются. Если установка отменена, проверенный файл остаётся доступен для повторного нажатия; при восстановлении приложения файл проверяется заново. Очистка кэша Android может удалить скачанный APK — в таком случае его нужно скачать повторно.

### Однократный переход со старых debug APK

Прежние сборки создавались с временными debug-ключами. Постоянный сертификат v0.24.0 отличается от сертификатов ранее выданных debug APK. Если такая версия установлена, потребуется один раз удалить её и установить подписанный v0.24.0. Перед удалением сохраните исходный WireGuard `.conf` вне приложения: удаление очищает профиль, исключения и локальные оценки Pushok ИИ. Последующие выпуски должны использовать тот же постоянный ключ и больший `versionCode`.

## Канал выпусков

- Репозиторий: `mrkoster1988/Pushok-Flow`.
- Описание актуального выпуска: `https://github.com/mrkoster1988/Pushok-Flow/releases/latest/download/update.json`.
- APK: `https://github.com/mrkoster1988/Pushok-Flow/releases/download/v<VERSION>/Pushok-Flow-v<VERSION>.apk`.
- Пакет: `shop.pushok.flow`; минимальная версия Android: API 24.
- SHA-256 постоянного публичного сертификата: `8b4114881116a920c3351b503052ac27078fdbbfcae1ace27f1af8245ebb7047`.

Схема `update.json` закреплена в `UpdatePolicy.kt`: версия схемы, имя пакета, версия приложения, номер сборки, минимальный SDK, адрес APK, его SHA-256, размер и отпечаток сертификата. Не добавляйте произвольные поля в схему 1.

Проверка принимает HTTPS-адреса этого репозитория и разрешённые адреса доставки файлов GitHub. Перед установкой проверяются размер и SHA-256 файла, пакет, версия, минимальный SDK, единственный текущий сертификат и превышение установленного номера сборки. Закрытый ключ подписи в APK, `update.json` и исходники не включается.

## Как подготовить следующий выпуск

1. Объединить законченные изменения в один выпуск. Увеличить версию и `versionCode` в `pubspec.yaml`, обновить отображаемую версию в информации о приложении.
2. Дождаться успешных проверок исходников и workflow **Android release candidate** для точного коммита.
3. Скачать APK-кандидат и набор официальных Android SDK Build Tools из артефактов того же запуска. Кандидат ещё не является распространяемым подписанным выпуском.
4. Подписать кандидат сохранённым постоянным ключом. Не создавать новый ключ при каждом выпуске. Ключ и пароли должны храниться вне репозитория и публичных артефактов.
5. Проверить подписанный APK через `tools/verify_release_apk.py`, затем сформировать три публичных файла через `tools/create_update_manifest.py`.
6. Убедиться, что номер сборки больше опубликованного в актуальном `update.json`, а сертификат совпадает. Создать тег `v<VERSION>` на проверенном коммите и выпуск GitHub с APK, его `.sha256` и `update.json`. Только после загрузки всех трёх файлов опубликовать выпуск как latest.
7. Проверить публичный `update.json` и соответствие файлов. Тогда установленное приложение сможет обнаружить новую версию.

Пример локальной подписи и проверки с установленными Android SDK Build Tools и Java. Пароли вводятся по запросу `apksigner`, а не записываются в команду или документацию:

```bash
zipalign -P 16 -f 4 app-release.apk app-aligned.apk
apksigner sign --ks /private/path/pushok-flow-release.p12 \
  --ks-key-alias pushok-flow-release --v4-signing-enabled false \
  --out app-signed.apk app-aligned.apk
python3 tools/verify_release_apk.py app-signed.apk \
  --expected-certificate-sha256 8b4114881116a920c3351b503052ac27078fdbbfcae1ace27f1af8245ebb7047 \
  --output release-verification.json
python3 tools/create_update_manifest.py --apk app-signed.apk \
  --verified release-verification.json --output dist
```

`android-release.yml` содержит дополнительный ручной workflow для полностью автоматической подписи и публикации после настройки четырёх GitHub Actions secrets: `PUSHOK_ANDROID_KEYSTORE_BASE64`, `PUSHOK_ANDROID_KEYSTORE_PASSWORD`, `PUSHOK_ANDROID_KEY_ALIAS`, `PUSHOK_ANDROID_KEY_PASSWORD`. Без этих secrets он намеренно завершится ошибкой. Для v0.24.0 используется сборка кандидата в CI и подпись постоянным ключом вне CI; автоматический выпуск через secrets не включён.

## Что подтверждается отдельно

Успешная сборка и проверка подписи подтверждают пригодность файла к передаче тестировщику. Реальное обновление на конкретном телефоне, сохранность его данных и работа VPN проверяются на устройстве. Первая версия с механизмом обновления может показать «Установлена актуальная версия»; полный сценарий обновления проверяется при публикации следующего выпуска с большим номером сборки.
