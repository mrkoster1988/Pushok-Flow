# Pushok Flow — быстрый вход и бесплатный WireGuard на 30 дней

## Пользовательский путь

1. Открыть Flow → «Войти через Telegram». Существующий пользователь MTProxy подтверждает вход в @mtproxy_pushok_bot. Новый пользователь регистрируется в том же MTProxy-аккаунте, **не в отдельной базе Flow**.
2. После подтверждения входа Flow получает scoped MTProxy access token. Через `POST /api/v1/flow/shop-ticket` запрашивает одноразовый билет для Shop; передаёт билет и случайный идентификатор устройства через `POST /shop/api/flow/bridge/exchange`.
3. При включённой серверной политике Shop создаёт **ровно один** бесплатный WG trial на пользователя, `days=30`. Работа с WGDashboard идёт только через Shop и его фоновый worker, не из APK. API выдаёт `pending` до подтверждения установки peer.
4. При `active` Flow забирает личный HTTPS feed `pushok-flow-subscription` v1, валидирует и сохраняет его в зашифрованном каталоге; для **новых установок** автоимпорт включён по умолчанию. Пользовательский выбор «выключить автополучение» сохраняется.
5. Показывается «Доступ бесплатно до <дата>», профиль выбран и доступна одна основная кнопка «Подключить». Первый запуск требует системного разрешения Android VPN; автоматическое подключение без него не разрешено.
6. По истечении 30 дней сервер удаляет/отключает peer в WGDashboard; запрет на новый старт в Flow недостаточен. Не продлевать бесплатно автоматически, не создавать второй trial после повторного входа.
7. Если пользователь удалил Flow, сменил аккаунт или телефон — не отдавать сохранённый приватный ключ другому аккаунту/устройству. Ротация отдельным подтверждённым сценарием.

## Существующие части

- Flow: `FlowAccount`, `FlowShopBridgeClient`, `ProfileSubscriptions.syncShop`, `WireGuardRouting`, шифрованный каталог.
- Shop: `flow_identity_bridge.py`, `flow_auto_provision.py`, `flow_wireguard`, `providers.py`.
- WGDashboard: отдельный узел `wg.pushok.shop`; действующий доступ официального WireGuard подтверждался ранее, **сквозная связка Flow ещё не проверена**.

## Обязательные условия серверного запуска

- Реальные MTProxy flow-ticket endpoints, подпись билета по `FLOW_SHOP_BRIDGE_SECRET`; одинаковый 32-байтный случайный ключ в переменной окружения **только серверов**, без логов.
- У Shop `flow_auto_policy.enabled=true`, `days=30`, разумный `max_users`; перед включением — HTTPS, условия сервиса, активный сервер WGDashboard с `schedule_expiry=true` и `panel_timezone`.
- Запущенный Shop worker, который обрабатывает очередь `process_pending`.
- Прокси-маршруты `pushok.shop` для MTProxy `/api/v1/flow/*` и Shop `/shop/api/flow/*`, `/shop/flow/wireguard/*` без конфликтов, без логирования bearer URL. Не перенаправлять ключи в веб-аналитику.
- Полный сценарий на физическом Android: регистрация → вход → pending → active → импорт → VPN permission → handshake/трафик → срок/отзыв.

## Не блокировать MVP

Платежи, Pushok ID, несколько устройств, автоматическая смена узла и платные подписки — следующие этапы, не нужны для первой бесплатной выдачи.

## Текущее ограничение

Изменение Flow в данной ветке лишь включает автоматический запрос личной подписки **для пользователей, которые ещё не сохраняли настройку**. Оно не развёртывает серверные endpoints, не включает trial-политику и само не запускает VPN. Эти шаги требуют отдельной серверной приёмки.
