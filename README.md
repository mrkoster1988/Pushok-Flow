Мобильное приложение Pushok Flow: WireGuard, выборочный прямой трафик приложений Android, фирменный неоновый интерфейс и локальная основа Pushok ИИ.

В v0.24.0 добавлен раздел **Профиль → Версия и обновления**: проверка выпуска, загрузка APK, разрешение установки и системное подтверждение Android. Для дальнейших обновлений используется один постоянный сертификат подписи. Подробный порядок: [docs/UPDATES.md](docs/UPDATES.md).

**Границы проверки:** запись установленной v0.22.0 подтверждает работу интерфейса, вкладок, исключений приложений, редактора профиля и локальной обратной связи Pushok ИИ. Скриншоты 21.11.2026 показывают главную и раздел обновлений работающей v0.24.0. Реальный туннель, маршруты и обновление поверх неё с сохранением данных ещё требуют испытания на телефоне.

## Опубликован v0.27.0

Опубликован единый выпуск `0.27.0+27` с накопленными изменениями v0.25–v0.26, упрощённой главной и импортом WireGuard из файла. Три кнопки «Серверы», «Маршруты» и «Pushok ИИ» убраны с главной; переходы остаются в нижнем меню. В защищённом редакторе добавлена кнопка **«Из файла .conf»**: Android открывает выбор одного файла, приложение проверяет содержимое и заполняет скрытый черновик. Сохранение остаётся отдельным действием.

Причина отсутствовавшего обновления установлена: v0.25 и v0.26 были CI-кандидатами и не публиковались в GitHub Releases. Обновлятор v0.24 читал существующий публичный `update.json`, в котором последней оставалась v0.24.0. Теперь APK с постоянным сертификатом и новым `versionCode`, контрольная сумма и новый `update.json` опубликованы вместе. [Независимая проверка публичного адреса](https://github.com/mrkoster1988/Pushok-Flow/actions/runs/44940754876) получила HTTP 200, `0.27.0` / `27` и точные ожидаемые байты без авторизации.

**Обновление с опубликованной v0.24.0:** «Профиль → Версия и обновления → Проверить обновления → Скачать → Установить обновление». Пакет и постоянный сертификат совпадают; удалять v0.24.0 не требуется. Само обновление и сохранность данных на телефоне ещё должны быть подтверждены.

## Предыдущий этап: v0.26.0

В исходниках подготовлена версия `0.26.0+26`: на главной появилась **Диагностика связи** с фактическими счётчиками WireGuard, временем последнего рукопожатия и временем работы туннеля. Статус **«Туннель включён»** описывает состояние локального туннеля; проверка доступности Интернета этим не подменяется. На [коммите `24ce02a`](https://github.com/mrkoster1988/Pushok-Flow/commit/24ce02a40e04c83f12e205e3223ac90f00911d94) успешно прошли 119 Python-тестов, 79 Flutter-тестов, четыре Kotlin-набора, анализ Dart и сборка Android-кандидата. Публичный APK этой версии пока не выпущен.

- Нулевой счётчик отличается от отсутствующих данных. При ошибке чтения, переходе состояния или сворачивании устаревшие показатели скрываются.
- Опрос выполняется в активном приложении каждые 10 секунд при включённом туннеле или неизвестном состоянии; карточку можно обновить вручную.
- Запоздалый ответ не возвращает старые счётчики после отключения или переподключения. Ошибка чтения состояния сохраняет возможность отключить ранее включённый туннель.
- Подсказка поясняет рукопожатие, накопленные байты и ограничения измерений. Никакие ключи, адреса узлов или исходные ошибки SDK в карточку не передаются.

Объём работы и проверка: [docs/RELEASE-v0.26.0.md](docs/RELEASE-v0.26.0.md).

## Предыдущий этап: v0.25.0

В версии `0.25.0+25` добавлены защита экрана редактора WireGuard и закрепление Dart/Flutter-зависимостей. Публичный APK этой версии не выпущен. CI на [коммите `5b6fc15`](https://github.com/mrkoster1988/Pushok-Flow/commit/5b6fc15e62370615f87a6289c233e0b3b3cedeec) подтвердил 119 Python-тестов, 55 Flutter-тестов, четыре Kotlin-набора, анализ Dart и сборку Android-кандидата.

- Android включает защиту от системного захвата экрана перед загрузкой профиля. Она действует до полного закрытия редактора; обычные экраны сохраняют возможность делать снимки.
- При переключении приложения конфигурация скрывается, клавиатура закрывается, многострочный черновик сохраняется. Возвращение не раскрывает ключ автоматически.
- Задержанные ответы после сворачивания или закрытия экрана не открывают редактор и не запускают новый запрос подключения. Ошибка защиты не разрешает открыть профиль.
- Настоящий `pubspec.lock` получен на закреплённом Flutter SDK. CI проверяет его через `--enforce-lockfile`, сохраняет состав зависимостей и запрещает их повторное разрешение при анализе, тестах и сборке.

Объём работы, результаты проверки и оставшиеся испытания: [docs/RELEASE-v0.25.0.md](docs/RELEASE-v0.25.0.md). Эти изменения не устанавливают причину предупреждения Play Protect для v0.24.0. Обращение в Google согласовано, но ещё не отправлено: официальная форма остановилась на CAPTCHA.

## Переход со старых debug APK

Постоянный сертификат отличается от временных сертификатов прежних debug-сборок. Для перехода с такой версии потребуется **один раз удалить старое приложение** и установить текущий подписанный выпуск. Это не относится к опубликованной v0.24.0 с постоянным сертификатом. Перед удалением debug-сборки сохраните исходный WireGuard `.conf` вне Pushok Flow и запишите выбранные исключения. Удаление очистит профиль, исключения и локальные оценки Pushok ИИ.

Следующие выпуски с тем же сертификатом и большим номером сборки предназначены для установки поверх приложения с сохранением данных. Их установку пользователь подтверждает в Android. SHA-256 постоянного публичного сертификата:

```text
8b4114881116a920c3351b503052ac27078fdbbfcae1ace27f1af8245ebb7047
```

## Что изменилось

- Добавлена проверка GitHub Releases и загрузка APK из раздела профиля. Перед установкой проверяются размер, SHA-256, пакет, версия и сертификат.
- Готовый APK восстанавливается после пересоздания приложения с повторной проверкой. Возврат из настроек разрешения сохраняет возможность продолжить установку явным нажатием.
- Включено исправление v0.23.0: кнопка сохранения WireGuard-профиля учитывает нижнюю системную область Android; клавиатура учитывается отдельно.
- Подсказка требует полный WireGuard `.conf` с `[Interface]` и `[Peer]`. Отдельный UUID отклоняется с понятным объяснением.

Полные заметки: [docs/RELEASE-v0.24.0.md](docs/RELEASE-v0.24.0.md).

## Разработка и проверки

Закреплены Flutter `3.50.0`, Material UI `1.11.1`, Java 17, Kotlin CLI `2.2.21` для самостоятельных проверок и WireGuard `1.0.20260102`.

```bash
python3 -m unittest discover -s tests -v
bash tools/check_kotlin_routing.sh
flutter pub get --enforce-lockfile
flutter analyze lib test --no-pub
flutter test --no-pub
```

`check_kotlin_routing.sh` проверяет пять модулей: маршруты WireGuard, диагностику туннеля, политику обновлений, владение защитой экрана и чтение импортируемого профиля. Путь выпуска: **CI-кандидат → локальная подпись постоянным ключом через apksigner → проверка итогового APK → публикация того же файла в GitHub Releases**. Для публикации GitHub восстанавливает точные байты подписанного APK из проверенного кандидата и публичного описания различий, сверяет SHA-256 и сертификат. Закрытый ключ в CI не передаётся; повторная сборка не выполняется. Подробности и отдельный будущий вариант с GitHub secrets: [docs/UPDATES.md](docs/UPDATES.md).

## Состояние проекта и следующий тест

Android WireGuard GoBackend, выбор исключений и локальная память оценок реализованы. На телефоне предстоит проверить настоящий туннель, DNS, IPv4/IPv6, прямые маршруты выбранных приложений и полный цикл обновления с сохранением данных. iPhone пока не реализован. Результаты устройства фиксируются в [задаче #1](https://github.com/mrkoster1988/Pushok-Flow/issues/1).

Внешний вид следует согласованным неоновым макетам и использует оригинального маскота: [docs/DESIGN-SYSTEM.md](docs/DESIGN-SYSTEM.md). Приватные ключи WireGuard, пользовательские конфигурации, закрытый ключ подписи и пароли не публикуются в репозитории, Issues или журналах.
